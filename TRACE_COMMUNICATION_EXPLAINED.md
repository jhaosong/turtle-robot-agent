# 2D Demo Trace Explained

This document explains how the printed `ROSA TRACE` lines in the original 2D TurtleSim demo are generated.

- who sends each command
- who receives it
- which function generates it
- which prompt/instruction causes that behavior
- how repeated trace patterns can be grouped

## What prompt causes this behavior

The behavior does not come from one single hardcoded workflow function.
It comes from the agent reading system prompts and deciding to call tools.

There are two prompt layers.

### Base ROSA system prompts

Defined in:

- [src/rosa/prompts.py](/Users/chenzhaosong/Downloads/rosa-main/src/rosa/prompts.py:64)

Important instructions:

- always check ROS state with tools first
- execute tools sequentially
- use tools one at a time
- use math/tools instead of handwaving

### Turtle-specific prompts

Defined in:

- [src/turtle_agent/scripts/prompts.py](/Users/chenzhaosong/Downloads/rosa-main/src/turtle_agent/scripts/prompts.py:18)

Important instructions for drawing:

- use high-level drawing tools like `draw_rectangle`, `draw_line_segment`, `draw_polyline`
- execute drawing commands sequentially
- use teleport-before-draw patterns to avoid angle drift
- for rectangles, draw each edge from a fresh exact pose

That is why the trace often shows:

```text
set_pen(off=1)
teleport_absolute(...)
set_pen(off=0)
publish_twist_to_cmd_vel(...)
```

The LLM is following the prompt guidance plus the tool docstrings.

## High-level to low-level command path

For the trace sample you attached, the repeated pattern strongly matches `draw_rectangle`.

- [src/turtle_agent/scripts/tools/turtle.py](/Users/chenzhaosong/Downloads/rosa-main/src/turtle_agent/scripts/tools/turtle.py:674) `draw_rectangle`

`draw_rectangle` internally issues four edge-drawing sequences.

Each edge is:

## Prompt-to-action map

This section avoids `sender` / `receiver` wording because that can sound like object messaging.

Instead, each step is described as:

- origin: where the information starts
- next executor: which code layer handles it next
- selected execution target: which tool/function the agent chose
- ROS endpoint invoked: which ROS service/topic is actually touched
- runtime consumer: which running ROS node acts on it

## Why some warnings appear between trace lines

Example:

```text
[WARN] [turtlesim]: Oh no! I hit the wall!
```

Sender:

- `turtlesim` node

Receiver:

- terminal log output

Generated by:

- the TurtleSim runtime itself, not by ROSA

Meaning:

- the previous `/turtle1/cmd_vel` movement pushed the turtle beyond the 11x11 boundary

This is not a trace print inserted by your code.

## Minimal end-to-end sequence

For a rectangle-like drawing request:

```text
User prompt
-> TurtleAgent.submit()
-> ROSA.astream() or ROSA.invoke()
-> formatted prompt built from base + turtle prompts
-> LLM selects draw_rectangle(...)
-> draw_rectangle()
-> set_pen(off=1)
-> /turtle1/set_pen
-> teleport_absolute(...)
-> /turtle1/teleport_absolute
-> set_pen(off=0)
-> /turtle1/set_pen
-> publish_twist_to_cmd_vel(...)
-> /turtle1/cmd_vel
-> turtlesim updates pose and drawing
```
